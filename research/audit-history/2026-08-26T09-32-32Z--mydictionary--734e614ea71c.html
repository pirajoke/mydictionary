MY DICTIONARY · 26.08.2026 · DATA RECONCILIATION

Пользователи не скрыты — часть старой базы не попала на OVH

Свежая production-сверка показывает 2 аккаунта: 1 админ и 1 ученик. На Mac mini до аварийного переноса было 3 ученика. Вкладка Pilot дополнительно вводит в заблуждение: она показывает только исторический waitlist и потому сейчас равна нулю.

Методология. Сопоставлены свежие агрегаты OVH PostgreSQL через DatabaseStore(..., migrate=False), обе поверхности админки, GitHub roadmap #6, журналы аварийного переноса и recovery-документы. Mac mini признан недоступным; дальнейшие действия ограничены локальными и off-site receipts. Секреты, learner IDs, имена, usernames, сообщения и ответы не выводились и не сохранялись. Каждый вывод помечен как ФАКТ / ГИПОТЕЗА / НЕИЗВЕСТНО.

Контуры внедрения и отсутствующие артефакты

Что можно автоматизировать уже сейчас и какие минимальные документы нужны, чтобы изменения не ломали production-контур.

7a. Контуры автоматизации

Единый язык интерфейса

ГОТОВО

Зачем: пользователь не должен попадать из французского урока в русскую ошибку, AI или оплату.

Сейчас: весь зарегистрированный Telegram user surface покрыт 8 локалями, locale persistence и behavioral-тестами.

Автоматизировать
locale persistence, coverage tests, placeholder parity, compatible-pair fallback.
Оставить человеку
тон, юридическую формулировку billing и культурную проверку.
Риск: learning content и интерфейс нельзя смешивать: русский перевод слова может быть корректным пользовательским выбором.

Найти historical source

P0

Зачем: без pre-cutover backup отсутствующих learners нельзя вернуть доказуемо.

Сейчас: Mac mini недоступен; post-cutover off-site object старые rows не подтверждает.

Автоматизировать
inventory timestamps, hashes, revisions, aggregate counts.
Оставить человеку
физический доступ к старому диску и точный recovery approval.
Риск: не принимать post-cutover backup за источник cohort 3.

Наблюдаемое удержание

P1

Зачем: понять, возвращается ли ученик после первой ценности.

Сейчас: public cohort 1; D1 1/1; D7 0/0 eligible.

Автоматизировать
daily aggregate D1/D7, N, freshness and health.
Оставить человеку
решение только при N≥10.
Риск: 100% при N=1 — направляющее, не доказательное значение.

Изолированный reconciliation

P0

Зачем: missing rows нужно добавить, не перезаписывая новые OVH данные.

Сейчас: только план; source backup не найден.

Автоматизировать
isolated restore, dry-run diff, duplicate/conflict report.
Оставить человеку
точный source, target и conflict policy.
Риск: restore или merge user data — отдельный NEEDS MARK gate.

Понятная админка

P1

Зачем: оператор должен сразу видеть all users и смысл legacy cohort.

Сейчас: Users=2, Pilot=0 без явного объяснения.

totals All / Learners / Admins / Public cohort.
Оставить человеку
название «Legacy pilot» и UX-приоритет.
Риск: фильтр не должен выглядеть как потеря данных.

Визуальный пилот карточек

P2

Зачем: усилить запоминание после исправления базового UX.

Сейчас: 0 word images / 901 entries.

Автоматизировать

Приоритеты

Сначала восстановить доверие к данным, затем улучшать продукт и набирать новую когорту.

Сейчас · read-only P0

  • Не менять текущую OVH database.
  • Инвентаризировать только существующие локальные/off-site artifacts: timestamps, hashes, schema/revision и aggregate counts.
  • Искать backup, созданный после cohort 3 и до 19.08.
  • Не считать post-cutover restore доказательством старых learners.
  • Сохранить точный source-of-truth plan и NEEDS MARK gate.

После отдельного owner gate · P0/P1

  • Назвать точный source backup, target isolated DB и conflict policy.
  • Восстановить source только в disposable database.
  • Сформировать privacy-safe dry-run: missing, duplicate и conflict counts.
  • После нового решения создать свежий OVH backup и транзакционно добавить только missing rows.
  • Проверить users/progress/events aggregates, heartbeat и admin health.

После reconciliation · P1/P2

  • Переименовать Pilot в Legacy pilot и показать All users / Learners / Admins.
  • Довести public cohort до ≥10 D7-eligible.
  • Завершить ручной Google OAuth callback smoke.
  • Оставить public Stars checkout off до отдельного launch-решения.
  • Продолжить визуальные карточки и нативную языковую редактуру.
  1. Собрать manifest существующих backup artifacts без их восстановления.
  2. Отсортировать по timestamp относительно 12–19.08.
  3. Проверить hash, archive format и revision metadata.
  4. Отметить кандидаты, способные содержать cohort 3.
  5. Сформировать отдельный recovery gate с source, target и conflict policy.

НЕИЗВЕСТНО. Существует ли локальный или off-site dump, созданный после cohort 3 и до первого Mac mini timeout 19.08.
НЕИЗВЕСТНО. Совпадает ли текущий learner с одним из трёх historical learner records.
НЕИЗВЕСТНО. Какие progress/events изменились после cutover и потребуют conflict resolution.
НЕИЗВЕСТНО. Были ли два отсутствующих аккаунта удалены до аварии; roadmap хранит aggregate, а не raw lifecycle rows.
